Oracle 메모리 & 프로세스 아키텍처

Oracle Instance 전체 구조

🔵 SGA 핵심 구성요소

  • Shared Pool — SQL 파싱 결과 공유 (Library Cache + Dictionary Cache)
  • Buffer Cache — 데이터 블록 캐싱, LRU 알고리즘으로 관리
  • Redo Log Buffer — 트랜잭션 변경 기록, LGWR가 디스크에 flush
  • Large Pool — 병렬 쿼리, RMAN 백업 전용

🟠 PGA 특징

  • 세션별 독립 메모리: 다른 세션과 공유 안 함
  • Sort Area: ORDER BY, GROUP BY 시 사용, 부족 시 Temp 파일 사용
  • Hash Area: Hash Join 시 Build Input 저장
  • WORKAREA_SIZE_POLICY = AUTO 시 Oracle이 자동 조절

⚙️ 핵심 Background Process

  • DBWn: Dirty Buffer를 데이터파일에 기록 (Checkpoint 시)
  • LGWR: Redo Log Buffer → Redo Log File (Commit 시 반드시)
  • CKPT: SCN 정보로 Checkpoint 기록 → 복구 범위 결정
  • SMON: 인스턴스 장애 복구, 임시 세그먼트 정리

SQL 파싱 & 실행계획 (Parsing & Execution Plan)

SQL 처리 단계 — Hard Parse vs Soft Parse
❌ Hard Parse — 성능 저하 원인
  • SQL 텍스트가 다를 때마다 발생 (공백/대소문자 포함)
  • Latch 경합 → CPU 과부하
  • Shared Pool 메모리 부족 시 빈번 발생
  • Literal 값 직접 사용 시 반복 발생
-- 매번 Hard Parse 발생 (나쁜 예)
SELECT * FROM emp WHERE empno = 7369;
SELECT * FROM emp WHERE empno = 7788;
SELECT * FROM emp WHERE empno = 7900;
✅ Soft Parse — 바인드 변수 활용
  • SQL 텍스트 동일 → Library Cache 재사용
  • Latch 경합 최소화, CPU 절약
  • Shared Pool 효율적 사용
  • 바인드 변수로 값만 교체
-- Soft Parse — 바인드 변수 사용 (좋은 예)
SELECT * FROM emp WHERE empno = :empno;
-- 첫 번째 실행: Hard Parse
-- 이후 실행: Soft Parse (재사용)
⚠️ 바인드 변수 주의사항: 컬럼의 데이터 분포가 극심하게 편향된 경우(히스토그램 필요), 바인드 변수 사용 시 최초 파싱 시 값을 기준으로 실행계획이 고정되어 오히려 성능 문제가 생길 수 있습니다. 이를 Bind Variable Peeking이라 하며, Adaptive Cursor Sharing(Oracle 11g+)으로 보완됩니다.

I/O 원리 & 성능 — DB 성능의 핵심

📌 핵심 원칙: 데이터베이스 성능 = I/O 최소화입니다. 같은 결과를 얻더라도 읽는 블록 수(논리적 읽기)를 줄이는 것이 가장 중요합니다.
I/O 종류 & 특성 비교

📊 I/O 비용 핵심 공식

-- 논리적 읽기 수 확인
SELECT sql_text, buffer_gets,
       disk_reads, executions,
       buffer_gets/NULLIF(executions,0) avg_lio
FROM   v$sql
ORDER BY buffer_gets DESC;

-- 실행계획에서 I/O 비용 확인
EXPLAIN PLAN FOR
SELECT * FROM sales WHERE cust_id = :1;
SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY);

⚡ I/O 최소화 전략

  • 인덱스 활용 — 필요한 블록만 액세스
  • 파티션 Pruning — 해당 파티션만 스캔
  • 클러스터 / IOT — 물리적 인접 저장
  • 컬럼 수 최소화 — SELECT * 지양
  • Result Cache — 동일 쿼리 결과 캐싱
  • Materialized View — 집계 결과 사전 계산

옵티마이저 (Optimizer) — CBO & RBO

CBO (Cost-Based Optimizer) 동작 원리
구분 RBO (Rule-Based Optimizer) CBO (Cost-Based Optimizer)
기준 미리 정해진 15가지 규칙 순위 통계정보 기반 비용(Cost) 계산
통계정보 불필요 필수 (정확도가 성능 좌우)
적응성 데이터 분포 무관 데이터 분포/볼륨에 적응
Oracle 지원 10g부터 공식 미지원 현재 표준 (기본값)
힌트 영향 RULE 힌트로 강제 다양한 힌트로 제어 가능
⚠️ 통계정보 문제 — 통계정보가 오래되거나 없으면 CBO가 잘못된 실행계획을 선택합니다.
해결: 주기적 ANALYZE 또는 DBMS_STATS 수행, Dynamic Sampling(OPTIMIZER_DYNAMIC_SAMPLING), Pending Statistics(11g+) 검증 후 적용

인덱스 구조 & 스캔 방식

B*Tree 인덱스 구조
인덱스 스캔 종류
인덱스 유형특징적합한 상황주의사항
B*Tree 인덱스 기본 인덱스, 정렬된 리프 구조 고 카디널리티, 범위/단건 검색 DML 부하, Fragmentation
Bitmap 인덱스 값별 비트맵 저장, AND/OR/NOT 연산 효율 저 카디널리티 컬럼 (성별, 상태코드), DW OLTP 환경 DML 심각한 Lock 문제
함수기반 인덱스 (FBI) UPPER(col), TO_CHAR(date) 등 표현식 인덱싱 함수 적용 컬럼 조건 검색 통계정보 갱신 필요, 표현식 일치해야 함
복합 인덱스 여러 컬럼 결합, 선두 컬럼 순서 중요 다중 조건 쿼리, 커버링 인덱스 선두 컬럼 조건 없으면 Range Scan 불가
클러스터 인덱스 (IOT) Index-Organized Table: 테이블 자체가 B*Tree 범위 검색 중심, PK 접근 빈번 Row Migration, Secondary Index 비효율
파티션 인덱스 Local / Global Partitioned Index 파티션 테이블과 함께 사용 Global Index: 파티션 DROP 시 UNUSABLE
🔑 클러스터링 팩터 (Clustering Factor): 인덱스 리프 블록을 순서대로 읽을 때 발생하는 테이블 블록 I/O 수.
값이 테이블 블록 수에 가까울수록 좋음 (물리적으로 인접 저장). 행 수에 가까울수록 나쁨 (랜덤 I/O 증가) → 인덱스 Range Scan 시 성능에 직결.

🎯 복합 인덱스 컬럼 순서 결정 원칙

-- 인덱스: (DEPTNO, JOB, SAL)
-- 선두 컬럼(DEPTNO) 조건 있어야 Range Scan 가능

-- ✅ 인덱스 사용 O
SELECT * FROM emp WHERE deptno = 10;
SELECT * FROM emp WHERE deptno = 10 AND job = 'CLERK';
SELECT * FROM emp WHERE deptno BETWEEN 10 AND 30;

-- ❌ 인덱스 사용 X (Full Table Scan)
SELECT * FROM emp WHERE job = 'CLERK';  -- 선두 컬럼 없음
SELECT * FROM emp WHERE sal > 2000;      -- 선두 컬럼 없음

-- ⚠️ 인덱스 부분 사용 (Range 후 필터)
SELECT * FROM emp
WHERE  deptno = 10 AND sal > 2000;  -- deptno만 Range, sal은 필터

순서 결정 원칙: ① = 조건 컬럼 우선 ② 카디널리티 높은 컬럼 우선 ③ 범위 조건 컬럼은 뒤로 ④ ORDER BY/GROUP BY 컬럼 고려

파티셔닝 (Partitioning)

목적: 대용량 테이블을 논리적으로 분할하여 관리성 향상 + 성능 향상(Partition Pruning)을 동시에 달성합니다.
파티셔닝 종류 & 특성

✂️ Partition Pruning — 핵심 성능 효과

-- Range Partition: ORD_DATE 기준
CREATE TABLE orders (
  ord_id   NUMBER,
  ord_date DATE,
  amount   NUMBER
) PARTITION BY RANGE (ord_date) (
  PARTITION p2023q1 VALUES LESS THAN (DATE '2023-04-01'),
  PARTITION p2023q2 VALUES LESS THAN (DATE '2023-07-01'),
  PARTITION p2023q3 VALUES LESS THAN (DATE '2023-10-01'),
  PARTITION p2023q4 VALUES LESS THAN (DATE '2024-01-01'),
  PARTITION p_max  VALUES LESS THAN (MAXVALUE)
);

-- ✅ 파티션 Pruning 발생 — p2023q3만 스캔
SELECT * FROM orders
WHERE  ord_date BETWEEN DATE '2023-07-01'
                  AND DATE '2023-09-30';
-- 실행계획: PARTITION RANGE SINGLE (또는 ITERATOR)

-- ⚠️ Pruning 불가 — 함수 적용 시
WHERE TO_CHAR(ord_date, 'YYYY') = '2023'  -- Full Partition Scan
인덱스 유형특징파티션 관리 영향
Local Partitioned Index 각 파티션마다 독립적 인덱스 세그먼트 파티션 DROP/TRUNCATE 시 인덱스 자동 관리
Global Partitioned Index 여러 테이블 파티션에 걸친 인덱스 파티션 DROP 시 UNUSABLE → Rebuild 필요
Global Non-Partitioned Index 일반 인덱스와 동일, 테이블만 파티션 가장 유연하나 관리 부담 있음

힌트 (Hints) 활용

힌트 기본 원칙: 힌트는 CBO가 잘못된 실행계획을 선택할 때 최후 수단으로 사용합니다. 힌트 남용은 코드 유지보수를 어렵게 합니다. 통계정보 갱신/재구성이 우선입니다.

🗂️ 접근 방식 힌트

-- Full Table Scan 강제
SELECT /*+ FULL(e) */ * FROM emp e
WHERE sal > 3000;

-- 특정 인덱스 사용 강제
SELECT /*+ INDEX(e emp_sal_idx) */ *
FROM emp e WHERE sal > 3000;

-- 인덱스 역방향 스캔
SELECT /*+ INDEX_DESC(e emp_sal_idx) */ *
FROM emp e WHERE sal > 3000;

-- Fast Full Index Scan
SELECT /*+ INDEX_FFS(e emp_sal_idx) */ *
FROM emp e;

-- 인덱스 Skip Scan
SELECT /*+ INDEX_SS(e emp_comp_idx) */ *
FROM emp e WHERE sal > 2000;

🔗 조인 방식 & 순서 힌트

-- NL Join 강제
SELECT /*+ USE_NL(d) */
       e.ename, d.dname
FROM   emp e, dept d
WHERE  e.deptno = d.deptno;

-- Hash Join 강제
SELECT /*+ USE_HASH(d) */
       e.ename, d.dname
FROM   emp e, dept d
WHERE  e.deptno = d.deptno;

-- 조인 순서 지정 (ORDERED: FROM 절 순서)
SELECT /*+ ORDERED USE_NL(d) */
       e.ename, d.dname
FROM   emp e, dept d  -- emp가 Driving
WHERE  e.deptno = d.deptno;

-- LEADING: Driving 테이블 지정
SELECT /*+ LEADING(e) USE_HASH(d) */
       e.ename, d.dname
FROM   dept d, emp e  -- 순서 무관, e가 Driving
WHERE  e.deptno = d.deptno;

⚡ 최적화 목표 힌트

-- ALL_ROWS: Throughput 최적 (기본)
SELECT /*+ ALL_ROWS */ * FROM big_tbl;

-- FIRST_ROWS(n): 첫 n행 빠르게 (화면 출력)
SELECT /*+ FIRST_ROWS(10) */ *
FROM   orders ORDER BY ord_date DESC;

-- 병렬 처리
SELECT /*+ PARALLEL(t 4) */
       SUM(amount)
FROM   sales t;

-- NL Join 배치 처리 개선
SELECT /*+ USE_NL(d) NL_AJ */
       e.* FROM emp e, dept d
WHERE  e.deptno = d.deptno;

-- 파티션 Pruning 힌트
SELECT /*+ PQ_DISTRIBUTE(t NONE NONE) */
       * FROM orders t
WHERE  ord_date >= DATE '2023-01-01';

🔧 기타 유용한 힌트

-- 서브쿼리 실행 방식
SELECT /*+ UNNEST */ *         -- 서브쿼리 풀기
FROM   emp
WHERE  deptno IN
       (SELECT deptno FROM dept WHERE loc='NY');

SELECT /*+ NO_UNNEST PUSH_SUBQ */ *
FROM   emp;

-- 힌트로 통계정보 무시
SELECT /*+ DYNAMIC_SAMPLING(t 4) */ *
FROM   new_tbl t;

-- 카디널리티 직접 지정
SELECT /*+ CARDINALITY(e 100) */ *
FROM   emp e;

-- Result Cache 사용
SELECT /*+ RESULT_CACHE */
       SUM(sal) FROM emp;

종합 튜닝 전략 — 체계적 접근

SQL 튜닝 우선순위 피라미드

🔄 서브쿼리 → 조인 변환

-- ❌ 느린 패턴: 상관 서브쿼리
SELECT e.*
FROM   emp e
WHERE  e.deptno IN (
  SELECT deptno FROM dept
  WHERE  loc = 'NEW YORK'
);

-- ✅ 빠른 패턴: 조인으로 변환
SELECT e.*
FROM   emp e
       JOIN dept d ON e.deptno = d.deptno
WHERE  d.loc = 'NEW YORK';

📊 부분범위 처리 패턴

-- ROWNUM을 이용한 페이징 (중요!)
SELECT *
FROM  (SELECT rownum rn, a.*
        FROM  (SELECT * FROM orders
               ORDER BY ord_date DESC) a
        WHERE  rownum <= 20)
WHERE rn >= 11;

-- 12c+: FETCH FIRST (더 간결)
SELECT * FROM orders
ORDER BY ord_date DESC
OFFSET 10 ROWS FETCH NEXT 10 ROWS ONLY;

🚫 인덱스를 못 쓰게 하는 패턴 (Anti-Pattern)

안티패턴문제 쿼리해결 방법
컬럼에 함수 적용 WHERE TO_CHAR(hire_date,'YYYY')='2023' WHERE hire_date BETWEEN DATE'2023-01-01' AND DATE'2023-12-31'
묵시적 형변환 WHERE emp_no = '7369' (emp_no가 NUMBER) WHERE emp_no = 7369 (타입 맞춤)
부정 조건 WHERE status != 'Y' 인덱스 구성 변경 또는 OR 분리
LIKE 앞 와일드카드 WHERE name LIKE '%홍길동' 역방향 인덱스 또는 Full-Text Index 검토
NULL 조건 WHERE col IS NULL 함수기반 인덱스: NVL(col, 'X') 인덱스
OR 조건 WHERE col1=1 OR col2=2 UNION ALL로 분리 + 각 인덱스 활용

🔍 성능 모니터링 핵심 V$ 뷰

-- 고부하 SQL 탐색 (buffer_gets 기준)
SELECT sql_id, executions, buffer_gets,
       disk_reads, elapsed_time/executions avg_ela,
       SUBSTR(sql_text,1,80) sql_text
FROM   v$sql
WHERE  executions > 0
ORDER BY buffer_gets DESC
FETCH FIRST 20 ROWS ONLY;

-- Wait Event 확인 (현재 세션)
SELECT sid, event, wait_class, seconds_in_wait
FROM   v$session
WHERE  status = 'ACTIVE'
AND    wait_class != 'Idle'
ORDER BY seconds_in_wait DESC;

-- Buffer Cache Hit Ratio
SELECT ROUND((1 - dr.value/NULLIF((dbg.value+cg.value),0))*100,2) hit_ratio
FROM   v$sysstat dr, v$sysstat dbg, v$sysstat cg
WHERE  dr.name  = 'physical reads'
AND    dbg.name = 'db block gets'
AND    cg.name  = 'consistent gets';

-- Shared Pool Hit Ratio (Library Cache)
SELECT namespace, gethits, gets,
       ROUND(gethitratio*100,2) hit_ratio
FROM   v$librarycache
WHERE  namespace = 'SQL AREA';
